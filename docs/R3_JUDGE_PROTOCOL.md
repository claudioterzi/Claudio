# R3-JUDGE/1 — local typed judgment under R³

Origin: **Claudio Terzi [CT-LGAI-001]**.

R3-JUDGE is an R³ epistemic layer around a Jev-compatible local decision backend. The first candidate backend is Rizzo Flow; R3-JUDGE is deliberately not branded as Jev and never treats a model score as factual evidence.

## Invariants

1. Every model judgment is `IPOTESI`, never `FATTO`.
2. Every response carries a falsification condition.
3. The backend/model id and evidence hash are recorded.
4. Nine sisters reading the same evidence are one evidence group, not nine independent confirmations.
5. Local candidate mode is not adoption. `active` mode requires a passing `adoption_gate.json` generated by the ten-file benchmark and matching the responding model/fingerprint.
6. If the local backend is unavailable or not admitted, existing behavior remains: configured hosted TypeSafe may answer; otherwise callers fall back to their deterministic path.
7. No backend judgment grants authority to send, publish, spend, deploy, delete, merge or otherwise mutate external state.

## Candidate installation on Claudio's Dell Latitude 5320 (i5-1145G7, 16 GB)

Rizzo Flow requires Python 3.11+, Git and `uv`. Pin the upstream revision used for evaluation so a later upstream change cannot silently change the benchmark:

```powershell
git clone https://github.com/Rizzo-AI-Academy/rizzo-flow.git
cd rizzo-flow
git checkout d34665b7a28c62b79f37939f2fd83f5fe659fbf9
uv sync --locked
uv run rizzo download --size 4b --quant q8_0
uv run rizzo devices
uv run rizzo serve --size 4b --quant q8_0 --device auto
```

The Intel Iris Xe / CPU path is not claimed here as benchmarked by R³. If the 4B Q8 model cannot run within the machine's shared memory, retry **the same 4B model** at `q4_k_m` before dropping to 1.7B:

```powershell
uv run rizzo download --size 4b --quant q4_k_m
uv run rizzo serve --size 4b --quant q4_k_m --device auto
```

The 1.7B model is acceptable for a smoke test, not automatically for adoption:

```powershell
uv run rizzo download --size 1.7b
uv run rizzo serve --size 1.7b --device auto
```

Before running R³ code, verify `http://127.0.0.1:8017/health` and keep the service bound to localhost unless an authenticated network exposure is intentionally designed.

## Candidate mode

Candidate mode lets the sisters call the local backend while preserving the `IPOTESI` label. It does **not** mean the backend is adopted:

```powershell
$env:R3_JUDGE_MODE="candidate"
$env:R3_JUDGE_BASE_URL="http://127.0.0.1:8017"
$env:R3_JUDGE_MODEL="rizzo-latest"
```

## Ten-file admission test

Create a JSON manifest with exactly 10 already-known outputs, five labelled `stub` and five `real`:

```json
{
  "fixtures": [
    {"id": "stub-1", "path": "path/to/stub1.txt", "label": "stub"},
    {"id": "real-1", "path": "path/to/real1.txt", "label": "real"}
  ]
}
```

Then run:

```powershell
python -m r3_judge.benchmark path/to/manifest.json --output r3_judge/adoption_gate.json
```

The user's minimum rule is recorded as `beats_chance = accuracy > 0.5`. R³ uses a stricter admission rule by default: at least **8/10**, at least **4/5 stubs** and **4/5 real outputs**, with one stable model/fingerprint across the run. Failure leaves `adopt: false`.

Only after a passing gate:

```powershell
$env:R3_JUDGE_MODE="active"
$env:R3_JUDGE_GATE="r3_judge/adoption_gate.json"
```

## Why this improves on a raw Rizzo connection

A raw Jev-compatible response is convenient but insufficient for R³. R3-JUDGE adds: explicit epistemic class, provenance, model/fingerprint binding, non-independence grouping, deterministic falsifiers, an admission gate, and fail-closed behavior. The inference backend can later be replaced by a native R³ logits engine without changing callers.

## Upstream attribution

The candidate backend is Rizzo Flow (Apache-2.0). This R³ layer does not copy its source code; it talks to its published HTTP interface. If R³ later incorporates or modifies Rizzo Flow source, Apache-2.0 attribution and NOTICE obligations must be preserved.
