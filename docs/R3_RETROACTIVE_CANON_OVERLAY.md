# R³∞ — RETROACTIVE CANON OVERLAY

Effective date: 16/09/2026
Status: CANONICAL REEVALUATION LAYER
Project signature: C.Terzi

## Purpose

This layer makes newly validated R³∞ principles apply retroactively whenever historical Raffaello decisions, architectures, agents, workflows or artifacts are reopened, reused or reevaluated.

It does **not** falsify history. Original timestamps, authorship, provenance, commits and prior decisions remain immutable evidence. The overlay changes the rule used for present-day interpretation and reuse.

## Retroactive rule

When a pre-overlay artifact is consulted, evaluate it as though the current canonical principles had been available at design time, then record the delta explicitly.

Required classification:

- `KEEP` — remains valid under current canon.
- `PATCH` — remains useful but requires a bounded change.
- `RETEST` — evidence is insufficient under current standards.
- `DEPRECATE` — should no longer guide new work.

Never silently rewrite the historical artifact merely to make it appear compliant.

## Mandatory current principles

For relevant work, reevaluation must consider the canonical Learning Watch of 16/09/2026:

1. `R3-021_CAUSAL_EXPLORATION`: CURRICULUM → ACTOR → VERIFIER; causal memory records `precondition, action, observed_effect, counterexample, evidence_hash, confidence`.
2. Verifier-gated orchestration: `verification_mode = deterministic | evidence_based | opinion`; only verifiable review may force loop-back.
3. `CAPABILITY_QUARANTINE`: acquired resource != activated authority; new capability remains quarantined until actual capability is resolved and fits the task authority envelope.
4. `R3-019_SENTINEL`: compact proxy benchmark for fast filtering; full benchmark remains mandatory before `AUTO_APPLY_ELIGIBLE`.
5. Native skill routing: treat routing as a specialized subsystem and compare metadata-in-context, embedding retrieval and hidden-state routing where technically possible.

Shared evolution loop:

`WATCH → EXTRACT → CANDIDATE PATCH → SANDBOX → BASELINE A/B → FALSIFICATION → AUDIT → ADOPT/REJECT → R³∞ MEMORY → NEW BASELINE`

## Historical replay procedure

For any historical decision or subsystem that becomes active again:

1. Preserve the original artifact unchanged.
2. Identify which current canonical principles are relevant.
3. Reconstruct the original objective, evidence and authority envelope where possible.
4. Evaluate with current tests, provenance requirements and safety gates.
5. Assign `KEEP | PATCH | RETEST | DEPRECATE`.
6. Record the reevaluation date, evidence hashes, benchmark deltas and rationale.
7. Only the resulting present-day decision may influence new work.

## Zero-Assunto

- Historical FACT remains historical FACT.
- Current interpretation is labeled INTERPRETATION.
- Retroactive applicability is a governance rule, not a claim that the rule literally existed in the past.
- No new principle becomes operational truth without reproducible evidence where testing is technically possible.

## Inter-agent requirement

Every Raffaello agent that reopens, reuses or extends historical R³∞ work must apply this overlay before treating the historical decision as current canon.

This creates functional retroactivity without corrupting provenance.
